01 / 이 페이지 자체가 제출물입니다왜 이 페이지를 따로 만들었나

공고의 필수 자격은 두 가지였습니다. HTML/CSS 퍼블리싱 실무 경험과 구조화 데이터를 직접 작성·적용해본 경험입니다.

앞의 것은 있습니다. 뒤의 것은 없었습니다. 실무 프로젝트에서 JSON-LD를 다뤄본 적이 없습니다. 그래서 서류에 "경험 없음"이라고 적는 대신, 지원 준비 기간에 직접 학습해서 이 페이지에 적용하고 URL로 제출합니다.

지금 보고 계신 페이지의 <head>에는 Person · ProfilePage · ItemList · FAQPage 네 개의 스키마가 하나의 @graph로 묶여 들어가 있습니다. 브라우저에서 페이지 소스 보기로 바로 확인하실 수 있습니다.

02 / 필수요건 ①HTML/CSS 퍼블리싱 실무

프레임워크를 쓰지 않고 순수 HTML과 CSS로 작업했습니다. 만든 것이 화면에 보이는 데서 끝나지 않고, 실제 판매 채널에 게시되어 매출로 이어졌습니다.

상품 상세페이지

860×1100 고정 규격. 외부 스타일시트로 클래스 체계를 분리해 상품마다 재사용했습니다. 완성본은 Chrome 헤드리스로 렌더링해 채널 규격 이미지로 내보냈습니다.

운영 대시보드

진행 상품과 단계별 상태를 한 화면에 모은 40KB짜리 수제 페이지. 누적 산출물 199건, 상품별 5단계 파이프라인 상태를 색으로 구분했습니다.

카드뉴스 자막 레이아웃

디자인 툴 API 대신 HTML로 자막을 조판하고 헤드리스 브라우저로 캡처했습니다. 같은 결과를 훨씬 낮은 비용으로 얻었습니다.

이 페이지

시맨틱 태그, 반응형 레이아웃, 다크 모드 대응, 키보드 포커스 표시를 적용했습니다. 외부 스크립트 의존이 없어 크롤러가 본문을 즉시 읽습니다.

03 / 필수요건 ②구조화 데이터 — 직접 작성한 것

이 페이지에 적용한 JSON-LD의 일부입니다. 전체는 페이지 소스에 있습니다.

// FAQPage — 생성형 검색이 가장 잘 인용하는 형태
{
  "@type": "FAQPage",
  "inLanguage": "ko-KR",
  "mainEntity": [{
    "@type": "Question",
    "name": "생성형 검색 최적화(GEO)는 기존 SEO와 무엇이 다른가요?",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "SEO는 검색 결과 목록에서 클릭을 받는 것이 목표이고,
              GEO는 생성형 답변 안에 인용되는 것이 목표입니다. ..."
    }
  }]
}

적용하며 이해한 것

  • @graph로 묶고 @id로 연결합니다. Person을 한 번만 정의하고 ProfilePage와 CreativeWork에서 @id로 참조하면 같은 인물이라는 사실이 한 곳에서만 관리됩니다.
  • 화면에 없는 내용을 스키마에 넣지 않습니다. 구조화 데이터는 본문의 요약이지 별도의 주장이 아닙니다. 어긋나면 스팸으로 판정됩니다.
  • inLanguage를 명시합니다. 한국어 콘텐츠임을 선언해야 언어 모델이 인용할 때 맥락을 잃지 않습니다.
  • FAQPage는 답변을 완결된 문장으로 씁니다. 앞 문장을 읽지 않아도 이해되는 단위여야 잘려서 인용돼도 뜻이 살아남습니다.

04 / 직무 이해GEO는 문장을 인용 가능한 단위로 끊는 일

검색 결과 목록에서는 제목과 요약이 클릭을 만듭니다. 생성형 답변에서는 문장 하나가 통째로 인용되거나 통째로 버려집니다. 그래서 GEO의 작업 단위는 페이지가 아니라 문장이라고 이해했습니다.

한 문장에 한 사실

"업계 최고 수준의 빠른 속도와 합리적 요금"처럼 두 주장을 붙이면 모델이 어느 쪽도 확신하지 못합니다. 끊어야 인용됩니다.

주어를 생략하지 않는다

"이 요금제는"을 "본 상품은"으로 바꾸면 인용된 순간 무엇에 관한 문장인지 사라집니다. 고유명사를 문장 안에 남깁니다.

수치는 문장 안에서 완결

표에만 있는 숫자는 인용되지 않습니다. 본문 문장으로 다시 한 번 서술해야 답변에 실립니다.

질문 형태로 표제를 단다

사용자가 실제로 묻는 문장을 제목으로 쓰면 질의와 문서 사이의 거리가 줄어듭니다.

이 원칙은 새로 배운 것이 아닙니다. 이커머스 콘텐츠에서 자막을 상품명이 아니라 "~하는 법" 같은 효용 문장으로 바꾸고, 마지막 장을 질문으로 끝내는 방식으로 이미 같은 일을 해왔습니다. 사람이 검색하는 방식과 모델이 인용하는 방식은 닮아 있습니다.

06 / 정직하게없는 경험

  • 검색광고 운영 경험이 없습니다. 광고비를 집행해 캠페인을 돌려본 적이 없습니다. 다만 판매 채널 4곳의 지표를 매일 보고 콘텐츠를 고쳐온 경험은 있습니다.
  • 통신업 경험이 없습니다. 규제 산업의 표기 기준은 지금부터 배워야 합니다. 대신 표시광고법을 의식하며 카피 규칙을 세워온 습관이 있습니다.
  • 구조화 데이터는 실무 경력이 아닙니다. 이 페이지가 첫 결과물입니다. 다만 "배우면 만들 수 있다"를 말이 아니라 URL로 제출합니다.

07 / 자주 묻는 것질문과 답

백영우는 어떤 HTML 퍼블리싱 경험이 있나요?
1인 이커머스를 운영하며 상품 상세페이지, 운영 대시보드, 카드뉴스 자막 레이아웃을 모두 HTML과 CSS로 직접 작성했습니다. 외부 프레임워크 없이 순수 HTML·CSS로 만들었고, 스타일은 외부 시트로 분리해 재사용했습니다. 완성된 페이지는 Chrome 헤드리스로 렌더링해 채널 규격에 맞는 이미지로 내보냈습니다.
백영우는 구조화 데이터를 다뤄본 적이 있나요?
이 페이지가 그 결과물입니다. Schema.org의 Person, ProfilePage, ItemList, FAQPage 타입을 JSON-LD로 직접 작성해 적용했습니다. 실무 프로젝트에서 구조화 데이터를 다룬 경력은 아직 없으며, 2026년 9월 SK텔레콤 GEO 담당자 채용에 지원하면서 직접 학습해 구현한 것입니다.
생성형 검색 최적화(GEO)는 기존 SEO와 무엇이 다른가요?
SEO는 검색 결과 목록에서 클릭을 받는 것이 목표이고, GEO는 생성형 답변 안에 인용되는 것이 목표입니다. 그래서 GEO에서는 키워드 밀도보다 사실의 명확성이 중요합니다. 하나의 문장이 하나의 사실만 담고, 주어와 수치가 문장 안에 완결되어 있으며, 질문과 답변이 짝을 이루고 있어야 언어 모델이 문맥을 잃지 않고 인용할 수 있습니다.
백영우는 AI 도구를 어떻게 활용하나요?
Claude Code와 Python으로 상품 정보 추출부터 문구 생성, 채널 등록까지 이어지는 파이프라인을 직접 구축했습니다. 상품 69건을 수기 입력 없이 등록했고, 고객 응대 초안을 자동 생성해 평균 응답 시간을 4시간에서 18분으로 줄였습니다. 발송과 집행은 자동화하지 않고 사람이 최종 확인합니다.
콘텐츠를 작성할 때 지키는 원칙이 있나요?
확인되지 않은 값은 쓰지 않습니다. 위탁 판매는 실물이 손에 없기 때문에 실측 치수와 소재 혼용률은 공급처가 제공한 값만 사용하고, 없으면 비워두고 확인이 필요하다고 표시합니다. 카피 생성 프롬프트에는 최상급·비교급 표현과 근거 없는 수치를 쓰지 않도록 하는 규칙을 고정으로 넣어두었습니다.
